# 수행평가 도우미 UI/UX 전면개편 실행 프롬프트

대상 저장소: `https://github.com/dy6553/performance-assessment-assistant`

## 역할
당신은 Next.js + React + Tailwind CSS 기반 교육용 웹/PWA의 시니어 UI/UX 엔지니어다.

현재 수행평가 도우미의 기능은 유지하면서, 모바일 사용성을 최우선으로 UI/UX를 전면 정리한다.
목표는 시험온에서 최근 정리한 방향처럼 **한 화면에 정보가 너무 많이 몰리지 않고, 사용자가 지금 해야 할 행동이 명확하며, 단계가 자연스럽게 이어지는 구조**로 만드는 것이다.

단, 수행평가 도우미는 시험온을 그대로 복제하지 않는다.
같은 제품군으로 보일 정도의 일관성은 유지하되 수행평가 도우미는 **보라색·청록색 계열의 독립적인 브랜드 인상**을 유지한다.

## 핵심 UX 원칙
- 한 화면에 한 가지 핵심 행동만 둔다.
- 수행평가 유형 선택, 업로드, AI 분석, 주제 선택, 계획 검토, 초안, 수정, 최종본을 한 화면에 모두 펼치지 않는다.
- 핵심 설명은 1~2줄로 제한하고 자세한 설명은 접는다.
- 완료된 단계는 간결한 요약 카드로 축소한다.
- 카드 안 카드의 과도한 중첩을 피한다.

## 디자인 방향
- 모바일 퍼스트
- 둥근 카드
- 넉넉한 여백
- 지나친 그라데이션과 그림자 금지
- 가장 중요한 CTA 하나만 진한 색
- 보조 버튼은 흰색/연한 배경
- 모바일 좌우 여백 `px-3 ~ px-4`
- 버튼 최소 높이 44~48px
- 데스크톱 최대폭 `max-w-5xl ~ max-w-6xl`

## 홈 화면
우선 확인:
- `src/app/page.tsx`
- `src/components/app-shell.tsx`
- `src/app/create/page.tsx`

홈은 기능 나열보다 시작 지점 중심으로 단순화한다.

상단:
- 수행평가 도우미 브랜드
- 짧은 한 줄 설명
- 진행 중 작업이 있으면 `이어서 하기`
- 없으면 `새 수행평가 시작`

핵심 기능은 최대 3개:
1. 수행평가 만들기
2. AI 주제 추천
3. 과제 안내 분석

보고서/발표/탐구 세부 유형은 홈에서 모두 설명하지 않고 `수행평가 만들기` 다음 화면에서 선택한다.

## 수행평가 만들기 흐름
관련:
- `src/app/create/page.tsx`
- `src/app/assignment/report/page.tsx`
- `src/app/assignment/presentation/page.tsx`
- `src/app/assignment/inquiry/page.tsx`
- `src/app/assignment/setup/[type]/page.tsx`
- `src/app/assignment/workspace/page.tsx`

단계:
1. 수행평가 유형 선택
2. 세부 유형 선택
3. 과제 조건 입력/업로드
4. AI 분석 결과 확인
5. 주제 선택
6. 계획 검토
7. 초안 작성
8. 검토/수정
9. 최종본

AI 분석 결과는 사용자가 확인 버튼을 눌러야 다음 단계로 이동한다.

## 진행 단계 UI
작업 중 상단에 진행률 표시.
모바일에서는 전체 단계를 늘어놓지 말고:
- `3 / 8`
- 현재 단계 이름
- 짧은 progress bar

완료 단계는 다시 수정할 수 있게 한다.

## AppShell / 모바일 내비게이션
대상:
`src/components/app-shell.tsx`

권장 모바일 하단 메뉴:
- 홈
- AI
- 만들기
- 기록
- 설정

캘린더는 홈/기록 쪽에서 접근하도록 이동을 검토한다.
상단 헤더는 로고, 로그인/내 계정, 필요 시 관리자만 우선한다.

## 로그인/회원가입
로그인 폼과 회원가입 폼을 동시에 펼치지 않는다.
첫 화면에서:
- 로그인
- 회원가입
을 먼저 선택하고 이후 해당 폼만 보여준다.

## AI 작업 진행
spinner만 보여주지 않는다.

예:
- 과제 안내 읽는 중
- 평가 기준 분석 중
- 주제 후보 만드는 중
- 계획 구성 중
- 초안 작성 중
- 독립 검토 중
- 결과 저장 중

백그라운드 작업은 화면을 벗어나도 계속 진행됨을 안내하고, 재진입 시 자동 복구한다.

## 오류/제한 UI
중요 오류는 공통 모달 사용:
- 동시작업 제한
- 서버 일시 오류
- AI 모델 응답 실패
- 업로드 실패

모달:
- 제목
- 간단한 설명
- 확인
- 필요한 경우만 다시 시도

기술 에러 코드나 stack trace는 노출하지 않는다.

## 다크모드
앱 자체 테마를 기준으로:
- 라이트
- 다크
- 시스템 설정 따르기

브라우저 강제 자동 다크모드에 의존하지 않는다.
`globals.css`의 배경, 테두리, hover, 입력창, 모달, 하단 내비게이션을 모두 점검한다.

## 모바일 검수
반드시 확인:
- 320px
- 360px
- 412px
- 태블릿
- 데스크톱

검수:
- 가로 스크롤 없음
- 버튼 잘림 없음
- 긴 제목 줄바꿈 정상
- 카드 화면 밖으로 나가지 않음
- 하단 내비게이션과 콘텐츠 겹침 없음
- 모달 잘림 없음
- safe-area 반영

## 접근성
- `aria-label`
- `aria-current`
- `role="status"`
- `role="alert"`
- `aria-live`
- 키보드 focus
- 최소 터치 영역
- 충분한 명도 대비

큰 글씨 모드에서도 UI가 깨지지 않아야 한다.

## 최종 목표
사용자가 수행평가 도우미를 열었을 때:
1. 무엇을 해야 하는지 바로 알 수 있고
2. 한 화면에서 너무 많은 정보를 보지 않아도 되며
3. 단계별로 자연스럽게 수행평가를 완성하고
4. 모바일에서도 앱처럼 편하게 사용할 수 있게 만든다.

디자인보다 **사용 흐름의 명확성, 가독성, 모바일 조작 편의성**을 우선한다.
