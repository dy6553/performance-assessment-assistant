# 수행도우미 사용자 진로 정보 및 수행평가 반영 설계

## 1. 목적

수행도우미의 사용자 정보에 진로 관련 정보를 저장할 수 있는 영역을 추가하고, 사용자가 원할 때 해당 정보를 수행평가 AI 작업에 참고하도록 한다.

핵심 원칙은 다음과 같다.

- 진로 정보 입력은 선택 사항이다.
- 사용자가 `AI 수행평가 작업에 진로 정보 반영`을 켠 경우에만 AI가 참고한다.
- 진로 정보보다 교사 안내문, 평가기준표·루브릭, 교과 적합성, 교육과정 조건을 우선한다.
- 모든 수행평가를 억지로 진로와 연결하지 않는다.
- 진로 정보가 자연스럽게 도움이 되는 주제·탐구 방향·사례·표현에서만 활용한다.
- 진로 정보가 꺼져 있거나 비어 있으면 기존 수행평가 동작과 동일하게 작동한다.

---

## 2. 사용자 정보에 추가되는 진로 항목

`내 계정 → 사용자 정보 → 진로 관련 정보`에서 다음 항목을 관리한다.

### 관심 진로 분야

예시:

- 인공지능
- 소프트웨어
- 의학
- 환경
- 경제
- 교육
- 디자인

최대 500자까지 저장한다.

### 희망 학과·전공

예시:

- 컴퓨터공학과
- 인공지능학과
- 생명과학과
- 의예과
- 경제학과

최대 300자까지 저장한다.

### 희망 직업·진로

예시:

- AI 엔지니어
- 의사
- 데이터 분석가
- 환경 연구원
- 교사

최대 300자까지 저장한다.

### 진로 관련 메모

사용자가 관심 있는 세부 분야, 앞으로 해 보고 싶은 탐구, 수행평가와 연결하고 싶은 방향 등을 자유롭게 입력한다.

예시:

> 인공지능 기술 중 교육 분야와 의료 데이터 분석에 관심이 있음. 가능하면 학교에서 직접 조사하거나 공개 데이터를 분석할 수 있는 주제를 선호함.

최대 1,500자까지 저장한다.

### AI 수행평가 작업에 진로 정보 반영

체크박스로 켜고 끌 수 있다.

- ON: 수행평가 AI 작업에 진로 정보를 참고
- OFF: 진로 정보는 계정에 저장만 하고 AI 작업에는 사용하지 않음

---

## 3. 데이터 저장 구조

수행도우미 Supabase의 `public.user_profiles`에 다음 필드를 추가한다.

```text
career_interest          text     관심 진로 분야
desired_major            text     희망 학과·전공
desired_career           text     희망 직업·진로
career_notes              text     진로 관련 메모
career_use_default        boolean  수행평가 AI 기본 반영 여부
```

기본값은 다음과 같다.

```text
career_interest = ""
desired_major = ""
desired_career = ""
career_notes = ""
career_use_default = false
```

기존 사용자 데이터는 그대로 유지하며 새 필드만 기본값으로 추가한다.

프로필 수정은 로그인된 사용자 본인만 가능한 기존 Supabase 인증 구조를 유지한다.

---

## 4. 수행평가 AI 반영 방식

사용자가 `career_use_default = true`로 설정하고 진로 정보가 하나 이상 입력되어 있을 때만 AI 작업에 진로 컨텍스트를 전달한다.

### 우선순위

AI는 다음 순서를 유지한다.

1. 교사 안내문
2. 교사 평가기준표·루브릭
3. 현재 수행평가 과목·단원·교육과정
4. 학생이 현재 수행평가에서 직접 입력한 생각과 자료
5. 사용자 프로필의 진로 정보
6. 일반적인 작성 관례

따라서 진로 정보 때문에 평가기준을 벗어나거나 과목과 무관한 주제를 만들지 않는다.

---

## 5. 단계별 반영

### 5.1 주제 추천

AI 주제 추천 시 다음 진로 정보를 함께 참고한다.

```text
관심 진로 분야
희망 학과·전공
희망 직업·진로
진로 관련 메모
```

예시:

사용자 정보:

```text
관심 분야: 인공지능
희망 전공: 컴퓨터공학과
희망 진로: AI 엔지니어
```

수행평가:

```text
과목: 통합사회
주제 조건: 지역사회 문제 조사
```

가능한 방향:

```text
학교 주변 디지털 정보 격차 문제와 AI·디지털 기술을 활용한 개선 방안
```

단, 교사 평가기준에 맞지 않거나 억지 연결이 되는 경우에는 진로 정보를 사용하지 않는다.

### 5.2 수행평가 요구사항·작성 전략 분석

주제가 확정된 뒤 AI가 작성 전략을 분석할 때 진로 정보가 자연스럽게 연결되는지 참고한다.

예시:

- 탐구 방향을 전공 관심과 연결
- 사례 선택 시 진로 분야와 관련된 사례 제안
- 결론에서 향후 탐구 방향을 진로 관심과 연결

진로 연결 자체가 평가요소가 아닌 경우에는 별도 필수 조건으로 만들지 않는다.

### 5.3 초고 작성

초고 작성 시 진로 정보가 유용한 경우 다음에 활용할 수 있다.

- 주제의 구체화
- 사례 선택
- 탐구 목적 설명
- 학생 관점의 문제의식
- 향후 탐구 방향

AI는 학생이 실제로 하지 않은 활동이나 경험을 진로 정보만 보고 만들어내지 않는다.

### 5.4 초고 수정·재실행

`요청사항대로 재실행` 기능에서 기존 초고와 사용자 수정 요청에 더해 활성화된 진로 정보를 참고한다.

사용자가 직접 요청한 수정사항이 진로 정보보다 우선한다.

### 5.5 AI Chat

모든 수행평가 단계의 AI Chat에서 현재 단계와 기존 결과물에 더해 진로 컨텍스트를 참고한다.

예시:

```text
사용자: 이 주제를 내 진로랑 조금 더 연결할 수 있어?
```

AI는 저장된 희망 전공·진로 정보를 바탕으로 현재 과목과 평가기준 안에서 가능한 연결 방향을 제안한다.

### 5.6 검증

검증 단계에서도 진로 정보가 활성화되어 있음을 알고 있지만, 검증 기준은 다음이 우선이다.

- 교사 요구조건 충족 여부
- 루브릭 충족 여부
- 논리성
- 사실·출처
- 형식·분량
- 학년 수준

진로와 연결되지 않았다는 이유만으로 감점 요소를 만들지 않는다.

## 6. 서버 처리 방식

사용자 진로 정보는 브라우저가 직접 AI 프롬프트에 임의로 삽입하는 방식이 아니라, 로그인 세션을 확인한 수행도우미 서버가 Supabase의 현재 사용자 프로필을 읽어 AI 요청에 필요한 경우에만 추가한다.

대상 API:

```text
/api/assignment/recommend-topic
/api/assignment/analyze
/api/assignment/generate
/api/assignment/revise-draft
/api/assignment/verify
/api/assignment/assistant
```

주제 추천에서는 전용 필드로 전달한다.

```text
interestField
desiredMajor
desiredCareer
```

작성·분석·검증 단계에서는 기존 학생 입력을 보존한 상태에서 서버 내부 AI 컨텍스트에 진로 참고 정보를 추가한다.

AI Chat에서는 별도의 `careerContext`로 전달해 현재 수행평가 원본 데이터를 변형하지 않는다.

---

## 7. 안전한 반영 규칙

AI는 진로 정보를 사용할 때 다음 규칙을 지킨다.

```text
진로 정보는 참고 정보다.
교사 안내·루브릭·교과 적합성을 항상 우선한다.
현재 수행평가에 자연스럽게 연결할 수 있을 때만 활용한다.
억지로 진로와 연결하지 않는다.
사용자가 실제로 하지 않은 경험·실험·조사·활동을 만들어내지 않는다.
진로 정보를 근거로 성적이나 진학 결과를 보장하는 표현을 하지 않는다.
```

## 수행평가별 진로 연계 O/X

수행평가 정보 입력 화면에는 `O`와 `X` 두 버튼을 둔다. 이 값은 계정 전체 설정이 아니라 현재 수행평가의 선택값이다.

- `O`: 현재 수행평가에서 저장된 진로 프로필을 참고한다. 계정 기본값이 OFF여도 이 수행평가에서는 사용한다.
- `X`: 현재 수행평가에서는 저장된 진로 프로필을 사용하지 않는다. 계정 기본값이 ON이어도 사용하지 않는다.
- 값이 없는 기존 수행평가/기존 API 요청: 기존 호환성을 위해 `career_use_default`를 따른다.
- 이 선택은 `user_profiles`에 새 컬럼을 만들지 않고 수행평가 입력 데이터(`careerLinked`)에 포함한다.
- 진로 정보 사용 시에도 교사 안내문, 루브릭, 교과 적합성, 학생의 직접 입력이 우선한다.

## 2026-09-05 진로연계 UX·회귀테스트 보완

진로연계 O/X 기능의 가시성·회귀 안정성·유지보수성을 다음과 같이 보완한다.

### 상태 가시성

- 주제 선택 화면에 `진로연계 O`, `진로연계 X`, 기존 데이터의 `진로연계 기본값` 배지를 표시한다.
- 작성 전략/초고 화면과 완성본 화면에도 같은 배지를 표시한다.
- 사용자는 현재 수행평가가 진로 정보를 사용하는지 다음 단계에서도 계속 확인할 수 있다.

### 회귀 테스트

`resolveCareerLinkUsage` 정책 함수를 분리하고 Node 기본 테스트 러너로 다음 3가지 핵심 경우를 자동 검증한다.

1. 수행평가 `O` + 계정 기본 `OFF` → 진로 정보 사용
2. 수행평가 `X` + 계정 기본 `ON` → 진로 정보 미사용
3. 기존 수행평가 `null` → 계정 기본값을 그대로 따름

기존 GitHub CI의 `Lint` 단계가 `npm run lint`를 실행할 때 회귀 테스트도 함께 실행되므로 별도의 workflow 권한 변경 없이 자동 검증된다. 그 뒤 Next.js production build를 검증한다.

### 설정 UI 단일화

실제 라우트가 사용하는 `CompactAssignmentSetup`을 수행평가 설정의 단일 구현으로 유지한다. `AssessmentWizard`에 남아 있던 레거시 `SetupScreen`과 중복 유형별 입력 구현·핸들러는 제거하고, 혹시 남아 있는 `screen=setup` 호출도 `CompactAssignmentSetup`으로 위임한다. 이에 따라 진로연계 O/X 검증과 입력 규칙을 한 곳에서 유지한다.
