# 시험온 · 수행도우미 멀티기기 암호화 자동백업/동기화 설계

작성일: 2026-09-05

## 1. 목표

시험온과 수행도우미를 휴대폰 1대만 사용하는 사용자와 휴대폰+태블릿 등 여러 기기를 사용하는 사용자가 별도 설정 없이 사용할 수 있도록 한다.

핵심 목표는 다음과 같다.

- 모든 작업 내용을 기기 로컬 저장소에 먼저 저장한다.
- 인터넷이 없어도 작업 가능해야 한다.
- 인터넷 연결 시 변경 내용을 자동으로 암호화해 서버에 백업한다.
- 같은 계정으로 로그인한 다른 기기가 있으면 자동으로 최신 데이터를 동기화한다.
- 서버에는 가능한 한 평문 학습/수행평가 내용을 저장하지 않고 암호화된 payload를 저장한다.
- 기기 1대 사용자와 2대 이상 사용자를 자동으로 구분한다.
- 기존 수동 암호화 백업 파일 기능은 비상 복구용으로 유지한다.

---

## 2. 최종 구조

```text
[휴대폰]
IndexedDB / OPFS
    ↓ 즉시 로컬 저장
변경 감지
    ↓
기기에서 암호화
    ↓
[Supabase]
암호문 + 버전 + 기기정보
    ↓
같은 계정의 다른 기기가 있을 때
    ↓
암호문 다운로드
    ↓
기기에서 복호화
    ↓
[태블릿]
IndexedDB / OPFS
```

폰과 태블릿이 직접 통신하는 구조가 아니라 Supabase를 암호화된 중계/백업 저장소로 사용한다.

---

## 3. 기기 수 자동 구분

사용자가 직접 “1대 사용자 / 2대 사용자”를 선택하지 않는다.

로그인한 기기마다 `device_id`를 발급하고 계정별 등록 기기 수를 기준으로 자동 동작한다.

예시:

```text
사용자 A
├─ Galaxy Phone  / device_01
└─ Galaxy Tab    / device_02

사용자 B
└─ Galaxy Phone  / device_03
```

### 기기 1대 사용자

- 로컬에 즉시 저장
- 서버에 암호화 자동백업
- 다른 활성 기기가 없으므로 다운로드 동기화 대상 없음

### 기기 2대 이상 사용자

- 각 기기에 로컬 저장
- 변경 내용을 서버에 암호화 자동백업
- 다른 기기에서 최신 버전을 확인
- 최신 암호문을 다운로드해 복호화 후 로컬 DB에 반영

기기 수가 늘어나도 같은 구조를 사용한다.

---

## 4. 기기 등록 정보

예시 테이블: `user_devices`

```text
id
user_id
device_id
device_name
platform
created_at
last_seen_at
last_sync_at
revoked_at
```

원칙:

- `device_id`는 설치/브라우저 프로필별 고유 ID
- 같은 계정이라도 기기마다 서로 다른 `device_id`
- 앱 실행/복귀 시 `last_seen_at` 갱신
- 로그아웃 또는 사용자가 연결 해제하면 `revoked_at` 기록
- 연결 해제된 기기는 새 동기화 데이터를 받지 못하도록 처리

---

## 5. 동기화 데이터 구조

예시 테이블: `encrypted_sync_records`

```text
id
user_id
record_id
record_type
version
source_device_id
updated_at
deleted_at
encrypted_payload
payload_iv
payload_schema_version
content_hash
```

필수 개념:

- `user_id`: 소유 계정
- `record_id`: 자료 고유 ID
- `record_type`: 문제, 시험결과, 프로젝트, 채팅, 캘린더 등
- `version`: 변경될 때마다 증가
- `source_device_id`: 마지막으로 수정한 기기
- `deleted_at`: 삭제 동기화를 위한 tombstone
- `encrypted_payload`: 기기에서 암호화한 실제 내용
- `content_hash`: 중복/변경 탐지용

---

## 6. 자동 저장/자동백업 흐름

```text
사용자 입력
↓
즉시 IndexedDB/OPFS 저장
↓
변경 큐에 등록
↓
약 1~2초 동안 추가 변경이 없으면
↓
기기에서 암호화
↓
Supabase 업로드
↓
동기화 완료 표시
```

추가 동기화 시점:

- 앱 실행
- 로그인 완료
- 화면 복귀
- 인터넷 연결 복구
- 프로젝트/시험 결과 저장 완료
- 수동 “지금 동기화” 버튼
- 일정 시간 동안 미동기화 상태가 지속된 경우

인터넷이 끊기면 서버 업로드 실패로 작업 자체를 실패시키지 않는다.

```text
인터넷 없음
→ 로컬 저장 성공
→ sync queue 유지
→ 인터넷 복구
→ 자동 재전송
```

---

## 7. 시험온 동기화 대상

권장 대상:

- 생성 문제
- 생성 시험
- 듣기 문제/결과
- 시험 결과
- 오답 데이터
- 시험 일정
- 사용자별 학습 설정
- 필요한 생성 결과 메타데이터

기존 로컬 저장 구조를 기본으로 유지하고 동기화 계층만 추가한다.

---

## 8. 수행도우미 동기화 대상

권장 대상:

- 수행평가 프로젝트
- 주제
- 조사 내용
- 초안
- 완성본
- AI 대화
- 캘린더
- 첨부파일 메타데이터
- 업로드한 PDF/사진/문서 원본

구조화 데이터는 암호화 payload로 DB에 저장한다.

대용량 파일은 기기에서 암호화한 뒤 Supabase Storage에 업로드한다.

```text
OPFS 파일
↓
기기에서 암호화
↓
Supabase Storage
```

---

## 9. 암호화 원칙

권장 암호화:

- AES-256-GCM
- 레코드/파일별 고유 IV
- 인증 태그를 통한 변조 검출
- 암호화는 업로드 전에 클라이언트에서 수행
- 다운로드 후 클라이언트에서 복호화

서버가 평문 학습 자료를 직접 다루지 않는 구조를 우선한다.

### 동기화 키

수동 백업처럼 매번 비밀번호를 입력하는 방식은 자동 동기화에 적합하지 않다.

권장 구조:

```text
계정별 동기화 키
↓
기기별 안전한 로컬 영역에 보관
↓
동기화할 때 자동 사용
```

새 기기를 연결할 때는 계정 인증 후 동기화 키를 안전하게 전달/복구하는 절차가 필요하다.

복호화 가능한 원본 키를 일반 DB 컬럼이나 로그에 그대로 저장하지 않는다.

---

## 10. 기기 간 동기화 예시

### 휴대폰에서 먼저 수정

```text
휴대폰 version 17
태블릿 version 16

휴대폰 수정
→ version 18
→ 로컬 저장
→ 암호화 업로드

태블릿 앱 복귀
→ 서버 version 18 확인
→ 암호문 다운로드
→ 복호화
→ 태블릿 로컬 version 18 적용
```

### 태블릿에서 수정

반대 방향도 동일하게 처리한다.

---

## 11. 충돌 처리

단순 `updated_at` 기준 덮어쓰기는 중요한 자료를 유실할 수 있으므로 버전 충돌 처리가 필요하다.

### 서로 다른 레코드를 수정

자동 병합한다.

### 한쪽 기기에서만 수정

최신 버전을 자동 적용한다.

### 같은 레코드를 두 기기에서 동시에 수정

기존 내용을 즉시 삭제하지 않는다.

```text
충돌 발생

휴대폰 버전
태블릿 버전

[휴대폰 버전 사용]
[태블릿 버전 사용]
[둘 다 보관]
```

초안/완성본 등 중요한 문서는 가능하면 충돌본을 별도 버전으로 보존한다.

---

## 12. 삭제 동기화

삭제 시 바로 서버와 다른 기기에서 완전 제거하면 오프라인 기기와 충돌할 수 있다.

따라서 tombstone 방식을 사용한다.

```text
삭제
↓
deleted_at 기록
↓
암호화 동기화
↓
다른 기기에도 삭제 상태 전달
↓
유예기간 경과
↓
최종 삭제
```

현재 두 앱의 7일 휴지통 정책과 연결하는 것을 권장한다.

---

## 13. 파일 동기화

대용량 파일은 DB payload에 직접 넣지 않는다.

예시 메타데이터:

```text
file_id
user_id
project_id
version
encrypted_storage_path
size
mime_type
content_hash
updated_at
deleted_at
```

파일 흐름:

```text
기기 OPFS
↓
파일 암호화
↓
Supabase Storage 업로드
↓
다른 기기에서 필요 시 다운로드
↓
복호화
↓
OPFS 저장
```

대용량 파일은 매 동기화마다 다시 받지 않고 해시/버전을 비교해 변경된 파일만 전송한다.

---

## 14. 동기화 상태 UI

각 앱에 공통적으로 다음 상태를 표시한다.

```text
✓ 동기화 완료
↑ 백업 중
○ 오프라인 - 기기에 안전하게 저장됨
! 동기화 충돌
! 동기화 실패 - 자동 재시도 예정
```

사용자가 서버 상태를 몰라도 현재 자료가 어디까지 저장됐는지 이해할 수 있어야 한다.

## 15. 내 기기 관리 화면

예시:

```text
내 기기

Galaxy Phone
현재 기기
마지막 동기화: 방금 전

Galaxy Tab
마지막 동기화: 오늘 10:42
[연결 해제]
```

기능:

- 등록된 기기 확인
- 현재 기기 표시
- 마지막 접속/동기화 시각
- 다른 기기 연결 해제
- 오래 사용하지 않은 기기 정리

## 16. 기존 수동 백업과의 관계

현재 구현된 수동 암호화 백업은 제거하지 않는다.

### 시험온

- `.examon-backup`
- 비상 복구용 전체 암호화 백업

### 수행도우미

- `.assessment-backup`
- 비상 복구용 전체 암호화 백업

최종 구조:

```text
평상시
→ 자동 로컬 저장
→ 자동 암호화 서버백업
→ 여러 기기 자동동기화

비상시
→ 사용자가 만든 암호화 백업 파일로 복구
```

자동 동기화와 수동 백업 파일을 함께 유지해 이중 안전장치를 만든다.

---

## 17. 권장 동기화 정책

| 상황 | 동작 |
|---|---|
| 기기 1대 | 로컬 저장 + 암호화 자동백업 |
| 기기 2대 이상 | 로컬 저장 + 암호화 자동백업 + 기기간 동기화 |
| 인터넷 끊김 | 로컬 저장 후 재연결 시 자동 업로드 |
| 새 기기 로그인 | 기기 등록 후 기존 암호화 데이터 동기화 |
| 같은 자료 동시 수정 | 충돌본 보존 후 사용자 선택 |
| 파일 변경 없음 | 재업로드/재다운로드 안 함 |
| 삭제 | tombstone 동기화 후 유예기간 뒤 완전 삭제 |
| 서버 장애 | 로컬 작업 정상 유지 |
| 수동 백업 | 기존 암호화 파일 방식 유지 |

## 18. 구현 순서

### 1단계 — 공통 기반

- `device_id` 생성/보관
- `user_devices` 테이블
- 기기 등록/해제
- sync queue
- version 관리
- 온라인/오프라인 감지

### 2단계 — 암호화 동기화

- 계정별 동기화 키 구조
- AES-256-GCM record encryption
- 암호화 업로드/다운로드
- 무결성 검사
- 재시도 로직

### 3단계 — 시험온 적용

- 생성 결과
- 오답
- 시험 결과
- 시험 일정
- 설정

### 4단계 — 수행도우미 적용

- 프로젝트
- 초안/완성본
- 채팅
- 캘린더
- IndexedDB/OPFS 첨부파일

### 5단계 — 멀티기기 충돌 처리

- version 비교
- 충돌 감지
- 충돌본 보존
- 사용자 선택 UI

### 6단계 — 기기 관리

- 내 기기 화면
- 현재 기기 표시
- 마지막 동기화
- 원격 연결 해제

### 7단계 — 안정화

- 오프라인 반복 테스트
- 폰↔태블릿 왕복 테스트
- 파일 대용량 테스트
- 동시 수정 테스트
- 삭제/복구 테스트
- 서버 장애 테스트

## 19. 완료 기준

다음 조건을 모두 만족하면 구현 완료로 본다.

1. 기기 1대 사용자는 별도 설정 없이 자동 암호화 백업된다.
2. 같은 계정으로 두 번째 기기에 로그인하면 자동으로 기기가 등록된다.
3. 두 기기에서 수정한 내용이 자동 동기화된다.
4. 인터넷이 끊겨도 작성/수정이 가능하다.
5. 재연결 시 누락된 변경분이 자동 업로드된다.
6. 동일 레코드 동시 수정 시 데이터가 조용히 사라지지 않는다.
7. 대용량 파일은 변경분만 동기화한다.
8. 연결 해제한 기기는 이후 동기화할 수 없다.
9. 서버에는 암호화된 payload 중심으로 저장한다.
10. 기존 `.examon-backup` / `.assessment-backup` 복구 기능이 유지된다.
11. 시험온과 수행도우미 양쪽에서 같은 기본 동기화 정책을 사용한다.

---

## 20. 최종 권장안

시험온과 수행도우미 모두 다음 원칙으로 통일한다.

> **Local-first + Client-side encryption + Encrypted cloud backup + Multi-device sync**

사용자가 기기 수를 직접 선택하지 않고 시스템이 계정에 연결된 활성 `device_id` 수를 기준으로 자동 처리한다.

- 1대: 자동 암호화 백업
- 2대 이상: 자동 암호화 백업 + 기기간 자동 동기화
- 인터넷 없음: 로컬에서 계속 사용
- 인터넷 복구: 자동 재동기화
- 충돌: 중요 데이터 보존 후 해결
- 수동 암호화 백업: 비상 복구용으로 계속 유지

이 구조를 시험온과 수행도우미의 공통 동기화 기준으로 사용한다.
